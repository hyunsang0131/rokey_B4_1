# bed_inspect: 실리콘 블록 침대 검사 공정

Doosan M0609 + OnRobot RG2, ROS2 Jazzy. 비전과 LLM 없이, 로봇이 블록을 하나씩 눌러 보고 강성으로 불량을 찾는다.

- **불량 교체 모드**: 6칸 측정 → 히트맵 → 불량 블록을 버리고 같은 높이 예비 블록으로 교체 → 재측정
- **측정만**: 1~3단계만 실행
메인 모드는 2개다 (자세한 내용은 8-1):
- **자동 보수**: 6칸 측정 → 빈칸과 "주변과 맞지 않는 모듈"(예: 40A 사이의 10A, 키 큰 큐브)을 찾음 → 보관대 큐브를 전부 눌러 보고 주변 강성에 맞는 것을 골라 채우고 바꿈(빼낸 모듈은 보관대로) → 재측정.
- **고객 맞춤**: 칸마다 **부드럽게 / 단단하게 / 높게** 중 하나를 고르면, 다른 종류가 들어 있는 칸과 빈칸을 원하는 큐브로 바꿈.

화면에서는 이 두 개만 바로 보이고, 아래 기존 모드는 "▸ 점검용 모드" 토글 안에 접혀 있다.
- 점검용 · **불량 교체 모드**: 6칸 측정 → 히트맵 → 불량 블록을 버리고 같은 높이 예비 블록으로 교체 → 재측정
- 점검용 · **측정만**: 1~3단계만 실행

롤러 단계는 2026-11-19 삭제했다 (9단계 공정). 커버는 기본으로 켜져 있고(`bed_config.COVER_ENABLED`, 환경변수 `BED_COVER=0` 이면 끔),
교시 위치 없이 `bed_config` 의 `COVER_*` 좌표(실물에서 교시한 3점)로 움직인다. 자세한 것은 `cover_movec.md` 와 5장.

실물 교시에 필요한 위치: `home`, `bed_1`~`bed_6`, `rack_1`~`rack_6`, `discard` (14개).

## 1. 설치

```bash
cp -r bed_inspect ~/ws_cobot_pjt/ws_dsr/src/
cd ~/ws_cobot_pjt/ws_dsr
colcon build --packages-select bed_inspect
source install/setup.bash
```

`DSR_ROBOT2` 를 쓰므로 기어 조립 때와 같이 PYTHONPATH 에 `install/dsr_common2/lib/dsr_common2/imp` 가 들어 있어야 한다.

## 2. 먼저 가짜 로봇으로 돌려 보기 (로봇 없이)

터미널 3개. 전부 `export ROS_DOMAIN_ID=80` 과 `source install/setup.bash` 를 한 상태에서:

```bash
# 터미널 1: 가짜 로봇 + 가짜 침대 (2번 블록이 불량인 상황)
ros2 run bed_inspect bed_sim --fault 2

# 터미널 2: 공정 노드 (가짜 교시 파일을 지정)
ros2 run bed_inspect bed_process ~/ws_cobot_pjt/teach_points/bed_sim.json

# 터미널 3: 화면
ros2 run bed_inspect bed_hmi
```

화면에서 "불량 블록 교체"를 고르고 **시작**. 2번 칸이 빨갛게 나오고, 교체 후 재측정에서 초록으로 바뀌면 정상이다.

자동 보수를 보려면 터미널 1 을 이렇게 띄운다 (3번 빈칸, 4번만 무른 큐브, 보관대에 무름/단단함 섞어서):
```bash
ros2 run bed_inspect bed_sim --bed 30,30,-,30,30,30 --bed-kind H,H,-,S,H,H \
    --rack 30,30,30,30,30,- --rack-kind S,H,S,H,S,-
```
화면에서 "자동 보수"(기본)로 시작. 3번은 보라(빈칸), 4번은 주황(맞지 않음)으로 나오고, 보관대에서 단단한 큐브 2개를 골라 넣는다.
"고객 맞춤"을 고르고 칸별 ▸ 토글을 펼쳐 3번·4번을 "부드럽게"로 바꾸면 부드러운 큐브를 넣는다. 키 큰 큐브까지 보려면 `--rack 40,30,30,30,40,-` 로 띄우고 "높게"를 고른다.

- `bed_sim` 을 다시 켜면 가짜 침대가 처음 상태로 돌아가므로 `bed_process` 도 다시 켠다.
- 가짜 로봇으로 돌릴 때의 재고/기록은 `~/ws_cobot_pjt/bed_data_sim` 에 따로 저장된다(실제 기록과 섞이지 않음).
- 가짜 로봇은 관절-좌표 계산이 단순 비례식이라 **자세와 충돌은 확인할 수 없다.** 공정 순서, 측정 계산, 화면 확인용이다.

## 3. 실제 로봇에 올리는 순서

### 3-1. 교시 (robot_setting direct_teach)

아래 이름 그대로 저장한 뒤, 만들어진 JSON 을 `~/ws_cobot_pjt/teach_points/bed.json` 으로 복사한다.

| 이름 | 어떤 자세 |
|---|---|
| `home` | 시작/끝 자세 |
| `bed_1` ~ `bed_6` | 각 블록 **중심 위**, 툴이 아래를 봄. 높이는 "블록을 잡고 지나가도 아무것도 안 닿는 높이" |
| `rack_1` ~ `rack_6` | 보관대 각 자리 중심 위. 높이 기준은 위와 같음 |
| `discard` | 불량 블록 버리는 통 위 |

칸 번호는 화면과 같다. 1→3번이 "길이 방향", 1→4번이 "폭 방향".

```
1 2 3
4 5 6
```

주의할 점
- 커버는 교시하지 않는다. `bed_config.py` 의 `COVER_*` 좌표로 움직인다(3-2, 5절 "커버 원호" 참고).
- 보관대 개수가 8개가 아니면 `bed_config.py` 의 `P_RACK`, `RACK_INIT` 을 맞게 줄이거나 늘린다. **빈 자리가 최소 1개** 있어야 한다.

### 3-2. 설정값 맞추기 (`bed_inspect/bed_config.py`)

꼭 실물에 맞춰야 하는 값:

| 값 | 뜻 | 맞추는 법 |
|---|---|---|
| `BLOCK_HEIGHTS`, `H_REF` | 블록 높이 3가지, 기준 높이 | 실제 블록 높이 |
| `BED_INIT`, `RACK_INIT` | 처음 재고 | 처음 한 번만 쓰임. 이후는 화면 "재고 수정" |
| `PRESS_APPROACH_DZ` | 교시 높이에서 빠르게 내려오는 양 | 내려온 뒤 손끝이 **가장 높은 블록의 천보다 5mm 이상 위** |
| `BED_PICK_DZ`, `RACK_PICK_DZ` | 교시 높이에서 블록 잡는 높이까지 | 기준 높이 블록으로 맞춘다. 다른 높이는 자동으로 보정 |
| `GRIP_WIDTH` | 그리퍼 폭 | 블록, 커버 고리 치수 |
| `COVER_GRIP_XYZ` | 커버 고리를 잡는 점 | x = 4번 블록 중심 x, y = 고리 위치(기본 -50), **z = 실제 고리 높이** |
| `COVER_DEMO_*` | 데모 시작점/경유점/끝점 | 경첩 위치와 각도를 여기서 계산한다. 뚜껑/경첩을 바꾸면 다시 잰다 |
| `COVER_REST_DEG`, `COVER_LINE_SEGMENTS` | 받침 각도, 경유→끝 직선 나누는 수 | 받침을 붙인 실제 각도 |
| `COVER_TCP` | 위 좌표를 잴 때의 TCP 이름 | 넣어 두면 TCP 가 다를 때 공정이 시작을 거부한다 |
| `GRIPPER_MODE` | `'service'`(/onrobot/sendCommand) 또는 `'io'`(디지털 출력) | 기어 조립 때 쓰던 방식이 디지털 출력이면 `'io'`. 파일을 안 고치고 `export BED_GRIPPER_MODE=io` 로도 바꿀 수 있다 |

### 3-3. 블록 1개 누르기 테스트

```bash
ros2 run bed_inspect press_test ~/ws_cobot_pjt/teach_points/bed.json
```

번호를 누르면 그 위치를 누르고 강성을 보여준다. 처음에는 `F_TARGET` 을 10 으로 낮추고 비상정지를 손에 든 채 한다.
확인할 것:
1. 같은 블록을 5번 눌렀을 때 강성이 ±5% 안에 들어오는가 (화면에 "흩어짐"으로 나옴)
2. 정상 블록과 일부러 나쁘게 만든 블록의 강성 차이가 30% 이상 나는가
3. R² 가 0.95 이상인가 (낮으면 `F_FIT_MIN` 을 올리거나 `F_TARGET` 을 키운다)
4. 로봇이 충돌 감지로 멈추지 않는가 (멈추면 `F_TARGET` 을 낮추거나 충돌 민감도를 조정)

이 결과로 `F_TARGET`, `WARN_RATIO`, `FAIL_RATIO` 를 정한다.

```bash
ros2 launch m0609_rg2_bringup bringup.launch.py mode:=real host:=192.168.1.100 model:=m0609
```

## 4. 파일 구성

| 파일 | 역할 | 로봇 필요 |
|---|---|---|
| `bed_config.py` | 설정값 전부. 현장에서 바꿀 숫자는 여기만 | |
| `bed_math.py` | 계산만: 강성, 불량 판정, 기울기, 교체 계획 | 아니오 |
| `bed_store.py` | 파일 저장: 교시 위치, 재고, 기준값, 측정 기록 | 아니오 |
| `bed_robot.py` | 로봇 기본 동작: 이동, 힘 읽기, 그리퍼. DSR_ROBOT2 를 감싼다 | 예 |
| `bed_tasks.py` | 동작 단위: 누르기, 커버, 블록 옮기기 | 예 |
| `bed_process.py` | 공정 노드: 9단계 순서, 모드, 화면과 통신 | 예 |
| `bed_hmi.py` | 화면: 히트맵, 버튼, 계획, 재고, 로그 | 아니오 |
| `bed_sim.py` | 가짜 로봇 + 가짜 침대 | 아니오 |
| `press_test.py` | 블록 1개 누르기 테스트 | 예 |
| `test/test_bed_math.py` | 계산 모듈 자동 테스트 | 아니오 |
| `test/test_cover_flow.py` | 커버 열기/닫기 순서 자동 테스트 (ROS 없이) | 아니오 |
| `test/e2e_sim.py` | 가짜 로봇으로 전체 공정 자동 테스트 | 아니오 |

부르는 방향은 한쪽이다: `bed_process → bed_tasks → bed_robot → DSR_ROBOT2`. 계산(`bed_math`)은 로봇과 무관해서 따로 테스트할 수 있다.

```
 bed_hmi  ──/bed/cmd──▶  bed_process ──▶ bed_tasks ──▶ bed_robot ──▶ DSR_ROBOT2 ──▶ 로봇
          ◀─/bed/status─      │
          ◀─/bed/log────      ├──▶ bed_math  (판정, 계획)
                              └──▶ bed_store (재고, 기준값, 기록 파일)
```

## 5. 파이프라인 9단계와 코드

| 단계 | 내용 | 코드 |
|---|---|---|
| 1 | 홈 위치 | `BedTasks.home()` |
| 2 | 실리콘 측정 | `BedTasks.press()` × 6 |
| 3 | 불량품 확인 | `bed_math.judge()` → 화면 히트맵. 교체 계획 `plan_replace()` |
| 4 | 커버 열기 | `BedTasks.cover_open()` : 고리 위에서 수직으로 내려가 잡고 원호(`amovec`) → y·z 직선(`amovel`) → 받침에 걸쳐 놓기 |
| 5 | 블록 빼기 | `BedTasks.move_block()` : 침대 → 버림(교체 모드) 또는 보관대(자동 보수) |
| 6 | 블록 넣기 | `BedTasks.move_block()` : 보관대 → 침대 |
| 7 | 커버 닫기 | `BedTasks.cover_close()` : 받침에 걸친 고리를 잡고 직선 거꾸로 → 원호 거꾸로, 닫히기 2도 전에 놓기 |
| 8 | 재측정 | `BedTasks.press()` × 6 |
| 9 | 정상 확인 | `bed_math.judge()` → 화면에 1차/재측정 나란히 |

(롤러로 천을 팽팽하게 하는 단계는 하지 않기로 해서 뺐다.) 자동 보수(repair)는 3단계에서 보관대 큐브를 살짝 닿기·누르기로 재고 `plan_fill()` 로 계획하고, 보관대에 놓기 전에는 빈자리인지 살짝 닿아 확인한다.

순서 전체는 `bed_process.py` 의 `_pipeline()` 한 함수에 위에서 아래로 적혀 있다.

불량이 없으면(교체 모드) 또는 옮길 블록이 없으면(자동 보수) 3단계에서 끝난다.

### 커버 열기/닫기 (4, 7단계)

뚜껑은 포맥스 판이고, 한쪽으로 치우친 경첩 2개가 있다. 데모 시작점은 경첩 두 개의 거의 가운데다. 베드 옆면에 약 110도 받침이 있어서, 다 열고 놓으면 뚜껑이 거기 걸친다.

데모 동작(`COVER_DEMO_START/VIA/END`)을 기준으로 한다: 고리를 Z 수직으로 내려가 잡고 → 시작점→경유점은 원호(`movec`) → 경유점→끝점은 x 그대로 y·z 만 바꾸는 직선 → 놓기.
`bed_math.cover_path()` 가 시작점과 경유점으로 경첩(y≈-240, z≈118, 축 = 베이스 X)을 구하고, 고리를 잡는 점(`COVER_GRIP_XYZ`)에 맞춰 같은 경첩 둘레로 좌표를 다시 만든다.
(데모 시작점을 넣으면 데모 경유점/끝점의 y, z 가 그대로 나온다: 테스트로 확인)

- 원호: 잡는 점 → 같은 각도(약 36도)의 경유점. 툴은 거의 수직.
- 직선: 경유점 → 끝점(데모와 같은 약 103도, 데모처럼 원보다 4% 바깥). `COVER_LINE_SEGMENTS`(기본 3) 개로 나눠 경첩 둘레를 따라간다. 1 이면 데모처럼 한 번에(가운데에서 원보다 약 32mm 안쪽).
- 놓으면 뚜껑이 받침(`COVER_REST_DEG` 110도)에 걸친다. 닫을 때는 받침에 걸친 고리 자리(`rest`)로 툴 방향을 따라 들어가 잡고 같은 길을 거꾸로, 완전히 닫히기 2도 전에 놓는다. (닫기는 데모로 아직 안 해 본 동작)

경첩 보호 (`bed_config.py` 의 "경첩 보호" 값):

| 장치 | 내용 |
|---|---|
| 가운데 잡기 | 잡는 점 x 가 데모 시작점 x 에서 15mm 넘게 벗어나면 시작 거부. 열고 닫는 동안 x 는 그대로 |
| 고리 높이 확인 | 잡는 점이 닫힌 뚜껑 면에서 10도 넘게 벗어나면 시작 거부 (z 오입력) |
| 각도 제한 | 끝점이 92도보다 덜 열리거나 받침 각도 이상이면 거부 |
| 순응 제어 | 뚜껑을 잡고 움직이는 동안 `task_compliance_ctrl([1000,1000,1000,50,50,50])` |
| 외력 감시 | `amovec`/`amovel` 로 출발시키고 0.05초마다 외력을 읽어, 순응 제어를 켠 직후 값보다 20N 넘게 변하면 즉시 정지 |
| 닫기 여유 | 완전히 닫히기 2도(약 7mm) 전에 놓아서 뚜껑을 테두리에 눌러 박지 않음 |
| 멈췄을 때 | 그리퍼를 열지 않는다 (놓으면 뚜껑이 떨어짐). 뚜껑을 손으로 받친 뒤 그리퍼를 연다 |

가짜 로봇에는 경첩 모델이 있다. 고리는 경첩 둘레 원 위로만 갈 수 있고, 벗어난 거리 x 강성(순응 1N/mm, 아니면 5N/mm)만큼 힘이 생기며, 40N 이 넘으면 "경첩 파손" 위반이다.
고리는 걸려 있는 것이라 25mm 놀이를 둔다(`--ring-slack`, 0이면 꽉 물음). 놓을 때 90도를 넘었으면 받침에 걸치고, 5도 안쪽이면 닫히고, 그 사이면 "쾅 닫힘" 위반이다.

## 6. 측정 원리 (2, 8단계)

힘 제어 모드를 쓰지 않고, **조금씩 내려가며 힘을 읽는다.** (`bed_tasks.py` 의 `press_at`)

1. 그리퍼를 닫고 칸 위(교시 높이)로 이동, 힘을 읽어 둔다.
2. `PRESS_APPROACH_DZ` 만큼 빠르게 내려온다. 힘을 15번 읽어 **영점**으로 잡는다.
   → 툴 무게 설정이 안 맞아도 "누르기 전과의 차이"만 쓰므로 상관없다.
   → 이때 힘이 이미 3N 이상 변했으면 천에 닿은 것이므로 측정하지 않고 오류로 표시한다.
3. 1mm 씩(접촉 후에는 0.5mm 씩) 내려가며 (높이, 힘)을 기록한다.
4. 힘이 `F_TARGET`(20N)에 닿으면 멈추고 교시 높이로 올라온다.
5. 힘이 `F_FIT_MIN`(5N) 이상인 점들을 직선으로 맞춘다: `힘 = k × (표면 높이 − 높이)`
   - 기울기 `k` = **강성 [N/mm]** → 불량 판정에 사용
   - 힘이 0 이 되는 높이 = **표면 높이** → 기울기 계산에 사용
   - R² 가 0.90 보다 낮으면 "측정 실패"로 두고 한 번 더 잰다.

안전장치: 힘이 `F_LIMIT`(40N) 초과, 접촉 없이 30mm 하강, 접촉 후 25mm 넘게 들어감 → 즉시 올라오고 그 블록을 오류로 표시.
앞의 두 경우 중 "접촉 없음"과 "너무 깊이 들어감"은 블록이 없거나 망가진 것이므로 불량으로 판정한다.

## 7. 불량 판정 (3, 9단계)

`차이 = (잰 강성 − 기준 강성) ÷ 기준 강성`. 15% 이상이면 주의(노랑), 30% 이상이면 불량(빨강).

기준 강성은
1. **기준값 저장**을 했으면 그 높이의 저장값
2. 안 했으면 이번에 잰 6개의 `(강성 × 높이)` 중앙값 ÷ 그 블록의 높이

2번은 "같은 재질, 같은 단면이면 강성 × 높이가 일정하다"는 성질을 쓴 것이다. 그래서 기울기 모드처럼 높이가 섞여 있어도 높은 블록(원래 더 무름)을 불량으로 오판하지 않는다.

**한계:** 2번 방식은 6개가 전부 같이 나빠지면 잡지 못한다(중앙값도 같이 내려가므로). 그래서 정상 블록으로 **기준값 저장을 한 번 해 두는 것**을 권한다.

## 8-1. 자동 보수 / 고객 맞춤 (빈칸 채우기 + 맞지 않는 모듈 교체)

준비물은 큐브 10개: **40A 6개, 10A 2개, 키 큰 10A 2개**(`TALL_HEIGHT`, 지금은 가정값 40mm → 실물을 재서 바꿀 것).
처음에는 침대 5개 + 빈칸 1개, 보관대 5개 + 빈자리 1개. 같은 높이의 10A/40A 는 겉모양이 같아서 **눌러 봐야만** 구분된다.
10A 와 키 큰 큐브는 "불량"이 아니라 정상 부품이다. 고치는 것은 "그 자리에 맞지 않는 모듈"이다.

큐브 종류는 측정으로 정한다: 표면 높이가 보통 큐브들(중앙값)보다 `TALL_DZ`(높이 차이의 절반) 이상 높으면 **높음**, 아니면 강성으로 **부드러움/단단함**.
측정 결과대로 재고의 높이(30mm / `TALL_HEIGHT`)를 고쳐 적으므로, 키 큰 큐브도 맞는 높이에서 집는다.

1. **빈칸**(`find_empties`): 닿지 않거나, 접촉 높이(3N 에 닿은 높이)가 가장 높은 칸보다 `EMPTY_DZ`(8mm) 이상 낮은 칸.
   강성으로 판정하지 않으므로, 끝까지 들어간 아주 무른 큐브(접촉 높이는 정상)를 빈칸으로 오판하지 않는다.
2. **보관대 2단계 측정** (`_press_rack_all`)
   - ① **살짝 닿기**(`touch_at`): 5개 모두 닿는 순간 멈추고 윗면 높이만 잰다 → 빈자리와 높은 큐브. 경계 = max(`TOUCH_F_MIN` 1N, `TOUCH_SIGMA` 5 × 영점 구간 노이즈 σ), `TOUCH_CONFIRM` 2번 연속 넘어야 닿음.
   - ② **누르기**: 보통 높이 큐브만 20N 까지 눌러 강성. 트레이에서 잰 값에 `RACK_TO_BED` 를 곱해 침대 기준으로 바꾼다. 높은 큐브는 누르지 않는다.
3. **맞지 않는 칸**
   - 이웃 기준(자동, `judge_auto`): 다른 칸들의 강성 중앙값과 비율이 `MISMATCH_RATIO`(0.5) 미만이거나 2배 초과. 중앙값이라 맞지 않는 칸 하나가 기준을 끌어내리지 않는다.
   - 이웃 기준에서는 키 큰 큐브도 맞지 않음(주변과 높이가 다름).
   - 고객 맞춤(`judge_profile`): 높은 큐브는 '높음', 나머지는 침대와 보관대에서 잰 강성을 로그 눈금에서 가장 크게 벌어진 곳으로 두 종류(부드러움/단단함)로 나누고(`split_classes`), 칸마다 원하는 종류와 다르면 맞지 않음.
4. **고르기**(`plan_fill`): 채울 칸마다 목표 강성과 **비율**이 가장 가까운 큐브. 목표는 이웃 기준이면 그대로 두는 이웃 칸들의 평균, 사용자 지정이면 원하는 종류의 대표 강성. 비율로 비교하므로 `RACK_TO_BED` 가 2배 가까이 틀려도 고르는 결과는 같다.
   고객 맞춤은 원하는 종류의 큐브 중에서 고르고(`plan_profile`), 모자라면 아무것도 옮기지 않고 어느 칸을 못 채우는지 오류로 알린다.
5. **예외 처리 — 놓기 전 확인**(`_check_rack_empty`): 모듈을 보관대에 되돌리기 전에 빈손으로 그 자리를 살짝 닿아 본다. 기록과 달리 큐브가 있으면 아무것도 들지 않은 채 홈에서 멈추고 "재고 수정 후 다시 시작"을 알린다.
6. **이동**(`plan_repair_moves`): 빈칸을 먼저 채우고, 맞지 않는 칸은 "그 모듈을 보관대 빈 자리로 되돌리기 → 고른 큐브 넣기". 버리지 않는다(다른 침대에서는 정상 부품). 보관대에 빈 자리가 없을 때만 버린다.
7. 재측정해서 빈칸과 맞지 않는 칸이 남지 않았는지 확인한다. 로그에 `RACK_TO_BED` 제안 값(침대에서 잰 값 ÷ 트레이에서 잰 값)이 나온다.

실물에서 먼저 맞출 값: `EMPTY_DZ`(press_test 로 빈칸과 10A 의 접촉 높이를 재 보고 둘 사이로), `RACK_TO_BED`(한 번 돌린 뒤 제안 값).

## 10. 정지와 오류

- **정지 버튼**: 지금 동작을 빠른 정지(`move_stop`)로 끊고 공정을 멈춘다. 누르던 중이었다면 누른 채로 두지 않고 교시 높이까지만 올라온다.
- 커버, 블록 옮기기 도중에 멈추면(정지, 오류, 전원 꺼짐 모두) "확인 필요" 표시가 파일에 남는다. 이 상태에서는 시작과 홈 이동을 모두 거부한다(그리퍼가 커버나 블록을 물고 있을 수 있어서). 물고 있는 것을 손으로 빼고, 실제 블록 위치와 커버 상태를 확인해 **재고 수정**에서 저장해야 풀린다.
- 커버가 열린 채 끝났다고 기록돼 있으면, 다음 시작 때 먼저 커버를 닫는다.
- 오류가 나면 그 자리에서 멈춘다. 자동으로 홈으로 가지 않는다(무엇과 부딪혔는지 모르므로). 화면 맨 위에 이유가 나온다.
- 정지 버튼은 소프트웨어 정지다. **위험할 때는 펜던트 비상정지**를 쓴다.

## 11. 화면과 주고받는 내용

전부 `std_msgs/String` 에 JSON 을 담는다(메시지 패키지를 따로 만들지 않기 위해).

| 토픽 | 방향 | 내용 |
|---|---|---|
| `/bed/cmd` | 화면 → 공정 | `{"cmd":"start","mode":"replace"}`, `{"cmd":"start","mode":"tilt","axis":"col","angle":3}`, `{"cmd":"start","mode":"repair","target":"auto"}`, `{"cmd":"start","mode":"repair","target":"user","profile":["hard","hard","soft","soft","hard","hard"]}`, `{"cmd":"stop"}`, `{"cmd":"calibrate"}`, `{"cmd":"home"}`, `{"cmd":"set_inventory",...}`, `{"cmd":"confirm"}`, `{"cmd":"cancel"}` |
| `/bed/status` | 공정 → 화면 | 상태 전체: 단계, 1차/재측정 결과, 교체 계획, 재고, 가능한 각도 |
| `/bed/log` | 공정 → 화면 | 로그 한 줄 |

화면 없이 터미널에서도 된다:
```bash
ros2 topic pub --once /bed/cmd std_msgs/String '{data: "{\"cmd\":\"start\",\"mode\":\"measure\"}"}'
```

공정 노드 안에는 스레드가 2개 있다. 메인 스레드는 로봇을 움직이고(DSR_ROBOT2 는 한 스레드에서만 써야 함), 통신 스레드는 명령을 받는다. 그래서 로봇이 움직이는 중에도 정지가 바로 들어온다.

화면 연동 검증(`test/hmi_live.py`)은 실제 화면의 버튼을 프로그램으로 눌러서 정지, 교체 모드(교체 전 확인 포함), 기울기 모드, 재고 수정 창을 끝까지 돌린다.

**하지 않은 것:** 실제 로봇에서는 한 번도 돌리지 않았다. 가짜 로봇의 힘은 "강성 × 눌린 깊이 + 노이즈"로 만든 값이고 자세 계산도 가짜라서, 아래 13번은 실물에서만 확인할 수 있다. 테스트는 Python 3.14 환경에서 돌렸고, 형님 PC 의 Python 3.12 로는 문법 검사만 했다.

## 13. 아직 실물로 확인해야 하는 것

가짜 로봇으로는 알 수 없는 것들이다.

1. **힘 측정 정밀도**: M0609 의 힘은 관절 토크로 추정한 값이다. 실제 노이즈와 반복 정밀도는 `press_test` 로 확인해야 한다(3-3).
2. **충돌 감지**: 20N 으로 누를 때 로봇이 충돌로 판단해 멈추는지.
3. **교시 자세와 경로**: 이동 중 침대나 보관대에 닿지 않는지. 처음에는 속도(`VELJ`)를 낮춰서 한 동작씩 확인한다.
4. **커버 원호**: `COVER_GRIP_XYZ` 의 z 가 실제 고리 높이인지, 순응 제어 중 `amovec` 가 받아들여지는지(에뮬레이터에서 먼저), 로그의 "최대 외력" 으로 `COVER_F_LIMIT` 맞추기. 처음에는 한 손을 비상정지에 둔다.
5. **그리퍼**: `'service'` 모드에서 폭 숫자가 실제 폭과 맞는지, 블록을 잡는 힘이 적당한지.
